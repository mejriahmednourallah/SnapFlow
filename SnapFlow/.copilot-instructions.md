## PROJECT OVERVIEW

SnapFlow is a comprehensive website auditing platform that analyzes websites across **9 audit axes** using a microservices architecture. The system crawls websites, applies NLP, computer vision analysis, and generates intelligent KPI-centric reports with security scanning and content analysis.

### Core Mission
Provide automated, AI-driven website intelligence across functionality, accessibility, performance, SEO, content quality, UX/UI, environmental impact, privacy/compliance, and security.

## THE 9 AUDIT AXES (Core Domain Knowledge)

| Axis # | Name (FR) | English Name | Key Metrics | Microsvc |
|--------|-----------|--------------|-------------|----------|
| 1 | **Audit Fonctionnel** | Functional Audit | Forms, CTAs, links, broken elements | Scanner |
| 2 | **Accessibilité & W3C** | Accessibility & HTML | WCAG AA compliance, contrast, ALT text | Scanner |
| 3 | **Performance** | Performance | LCP, FCP, CLS, image optimization | Scanner |
| 4 | **Audit SEO** | SEO Audit | Meta tags, sitemap, robots.txt, hierarchy | Scanner |
| 5 | **Audit de Contenu** | Content Audit | Readability, keywords, freshness | NLP Worker |
| 6 | **Audit UX/UI** | UX/UI Audit | Responsiveness, navigation, hierarchy | VRT (Visual) |
| 7 | **Eco Index** | Environmental Score | Page weight, requests, efficiency | Scanner |
| 8 | **RGPD & Conformité** | Privacy & Legal | Cookie consent, Policy, DPO contact | Scanner |
| 9 | **Check Sécurité** | Security Check | SQLi, XSS, SSL/TLS, DDoS signals | Scanner |

### KPI Scoring
- Each axis has **0-100 score** (weighted metrics)
- **Passing threshold**: Typically ≥70
- **User Preference**: Passing KPIs must NOT display risk wording ("Risque", "Manque à gagner")

## DATA FLOW: FROM SCAN REQUEST TO REPORT

### 1. User Initiates Scan (Frontend)
```typescript
POST /api/scans
{
  url: "https://example.com",
  depth: 2,
  include_screenshots: true
}
→ Returns scan_id (UUID)
```

### 2. Aggregator Orchestrates
- Creates `scans` record (status: PENDING)
- Creates `scan_pages` entries (one per URL)
- Distributes work to specialis services

### 3. Scanner Crawls (Go, ~2-5min)
- Uses Colly + go-rod
- Extracts: HTML, CSS, JS, images, links
- Computes: Performance (LCP, CLS), SEO, Security, Accessibility, Eco
- Stores Tier 1 metrics → `scan_pages.tier1_metrics` (JSONB)
- Updates status → CRAWL_COMPLETE

### 4. NLP Worker Processes (Python, async)
- Polls for pages with `tier2_metrics = NULL`
- Extracts text content → NLTK analysis
- Computes: Readability, keywords, sentiment, uniqueness
- Stores → `scan_pages.tier2_metrics` (JSONB)
- Updates status → NLP_COMPLETE

### 5. Visual Regression Runs (Python, async)
- Takes screenshots (desktop + mobile viewports)
- Computes SSIM, edge complexity, CTA saliency
- Stores 4 KPI values → `scan_pages.vrt_metrics`
- Updates status → VRT_COMPLETE

### 6. Aggregator Builds Report
- Polls `scan_pages` → ALL statuses COMPLETE
- Invokes `kpi_builder.py`:
  - Aggregates metrics across all pages
  - Normalizes to 0-100 per axis
  - Applies weighting/thresholds
- Invokes `classifier.py`:
  - Generates natural-language findings
  - Suggests roadmap priorities
- Updates `scans.report` (JSONB) with final KPIs
- Status → COMPLETE

### 7. Frontend Polls & Displays
```typescript
useAsyncAuditPoll(scan_id) → polls every 2sec
When status COMPLETE:
  Display 9 axes gauges
  Show findings + roadmap
  Offer PDF export
```

## KEY CONCEPTS & PATTERNS

### 1. **Async Coordination Pattern**
All services are **stateless** and coordinate via **PostgreSQL**:
```python
# Worker pattern (NLP, Visual, etc.)
while True:
    rows = db.query("SELECT * FROM scan_pages WHERE tier2_metrics IS NULL")
    for row in rows:
        result = process(row.html)
        db.update(row.id, tier2_metrics=result)
    time.sleep(3)  # Poll interval
```

### 2. **JSONB Flexible Schema**
- `tier1_metrics`: `{performance: {...}, security: {...}, ...}`
- `tier2_metrics`: `{readability: 0.85, keywords: [...], ...}`
- `vrt_metrics`: `{ssim: 0.92, complexity: 45, cta_saliency: 0.88, ...}`

### 3. **KPI Formula Pattern**
```python
def calculate_kpi(tier1, tier2, vrt):
    # Aggregate metrics
    perf_score = (tier1.lcp_score + tier1.cls_score) / 2
    content_score = (tier2.readability + tier2.uniqueness) / 2
    ux_score = (vrt.ssim + vrt.cta_saliency) / 2
    
    # Normalize & weight
    final_score = (perf_score * 0.4 + content_score * 0.3 + ux_score * 0.3)
    return max(0, min(100, final_score))
```

### 4. **Passing KPI Display Rule** ⭐
**USER PREFERENCE APPLIED**: If KPI score ≥ 70 (passing), do NOT show:
- "Risque" (Risk)
- "Manque à gagner" (Missed opportunity)
- Negative risk language
- Show: "✓ Compliant", "Well optimized", positive framing

Example in React:
```typescript
const showRiskWording = kpiScore.value < 70;
return (
  <div>
    <h3>{kpiScore.name}</h3>
    <ScoreGauge value={kpiScore.value} />
    {showRiskWording ? (
      <p>⚠️ Risque: Amélioration recommandée</p>
    ) : (
      <p>✓ Score Acceptable - Keep monitoring</p>
    )}
  </div>
);
```

### 5. **Report Generation Pipeline**
```
scan_pages (all complete) 
  → kpi_builder.aggregate() 
  → kpi_builder.normalize() 
  → classifier.generate_findings()
  → @react-pdf/renderer (Frontend)
  → PDF + PNG images (download)
```

## CODING CONVENTIONS & PATTERNS

### React Components
- Use **functional components** with hooks
- Prefer **Shadcn/UI** for components (Button, Dialog, Tabs, etc.)
- **TypeScript**: Always type props, return types
- **Tailwind**: utility-first, responsive-first
- **React Query**: useQuery/useMutation for server state

```typescript
// Example pattern
import { useQuery } from '@tanstack/react-query';
import { Button } from '@/components/ui/button';

  scanId: string;
}

export function AuditReport({ scanId }: AuditReportProps) {

  });

  return (
    <div className="space-y-4">
      <h1>Audit Report</h1>
      {isLoading ? <Spinner /> : <ReportDisplay data={data} />}
    </div>
  );
}
```

### Python Backend
- **FastAPI** for all APIs
- **Async/await** for I/O operations
- **SQLAlchemy ORM** for database (consistent across services)
- **Type hints** everywhere (Python 3.9+)
- **Logging**: structured logs (json format)

```python
# Example pattern
from fastapi import FastAPI, HTTPException
from sqlalchemy import select
from typing import Optional

app = FastAPI()

@app.post("/scans")
async def create_scan(url: str, depth: int = 2) -> dict:
    """Initiate a new website audit"""
    scan = Scan(url=url, depth=depth, status="PENDING")
    db.add(scan)
    await db.commit()
    return {"scan_id": scan.id, "status": "PENDING"}
```

### Go Services
- **Functional approach** (no large classes)
- **Interface-driven** design
- **Error handling**: explicit (if err != nil)
- **Goroutines** for concurrent processing

```go
// Example pattern
func AnalyzeURL(ctx context.Context, url string) (map[string]interface{}, error) {
    collector := colly.NewCollector()
    results := make(map[string]interface{})
    
    collector.OnHTML("a", func(_ *colly.HTMLElement, element *HTMLElement) {
        // Process links
    })
    
    if err := collector.Visit(url); err != nil {
        return nil, fmt.Errorf("failed to visit %s: %w", url, err)
    }
    
    return results, nil
}
```

1. **Backend**: Add calculation to `kpi_builder.py`
   ```python
   def calculate_new_metric(scan_pages):
       # Aggregate from tier1/tier2/vrt metrics
       return normalized_score  # 0-100
   ```
2. **Frontend**: Add gauge UI in `ScoreGauge.tsx`
3. **Database**: Add JSONB field if needed
4. **Test**: Verify score calculation with test data

1. **Check user preferences**: Don't show risk wording if score ≥ 70
2. **Update component**: `audit/AuditReportPage.tsx`
3. **Maintain 9 axes**: Don't remove any existing axes
4. **Style**: Use Tailwind + Shadcn/UI patterns

1. **Scanner**: Add analyzer in `v3-scanner-go/analyzers/`
2. **Store**: `tier1_metrics.security.{new_check}`
3. **Classify**: Update `classifier.py` to include in findings
4. **Display**: Add to Security Check (Axis 9) in report

1. **Hook**: Add to `useRedmineIntegration.ts`
2. **Service**: Create in `services/redmineService.ts`
3. **Error handling**: Use React Query error boundaries
4. **Types**: Define in `types/redmine.ts`

## PERFORMANCE CONSIDERATIONS

- **Scanner crawl time**: ~2-5 minutes (depends on page count, JavaScript)
- **NLP processing**: Async, non-blocking (runs independently)
- **Visual Regression**: 1-2 min per URL (screenshot + comparison)
- **Report generation**: <1 sec (aggregation only)
- **Frontend polling**: 2-second intervals (balance UX vs. server load)

### Optimization Opportunities
1. Implement Redis caching for repeated URLs
2. Parallelize NLP worker instances (KEDA scaling)
3. Cache screenshot baselines (reduce VRT time)
4. Progressive report generation (stream findings as ready)
